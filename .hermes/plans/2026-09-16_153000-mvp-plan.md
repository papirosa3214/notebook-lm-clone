# NotebookLM Clone — MVP Implementation Plan

> **For Hermes:** После согласования плана — реализация через subagent-driven-development по задачам.

**Goal:** Веб-приложение (Vite + React + TS) в духе Google NotebookLM: пользователь добавляет источники (URL, PDF/DOCX/TXT/MD, YouTube-видео), ведёт диалог с LLM-ассистентом с цитатами, сохраняет результаты как markdown-заметки-артефакты.

**Architecture:** Клиент (React 19 + shadcn/ui + Tailwind) ↔ Backend API (Node + Fastify + TypeScript) ↔ Провайдеры (Anthropic / OpenAI / Ollama на .110). **Векторное хранилище и retrieval — существующий Ragflow на .110** (infiniflow/ragflow:v0.25.5-cu12, http://192.168.1.110:8080) вместо собственного индекса: каждый «ноутбук» = Ragflow dataset, чанки и embeddings хранятся там, retrieval идёт через `/api/v1/retrieval`. Чанкер и эмбеддинги — через Ragflow (использует встроенные bge-m3 / mxbai). Чат стримит ответы через SSE с inline-цитатами. Артефакты — markdown в SQLite.

**Деплой:** сразу на `.110` в Coolify (рядом с Ragflow и TaskFlow). Без авторизации.

**Tech Stack:**
- Frontend: Vite 5, React 19, TypeScript 5, Tailwind CSS 4, shadcn/ui, TanStack Query, Zustand, react-markdown, react-syntax-highlighter
- Backend: Node 22, Fastify 5, TypeScript, Drizzle ORM + SQLite (better-sqlite3), Zod
- **Vector store / Retrieval: Ragflow v0.25.5 на .110** (вместо собственного индекса)
- LLM: Anthropic SDK, OpenAI SDK, Ollama HTTP API
- Парсинг файлов: локально в Node — pdf-parse (PDF), mammoth (DOCX), youtube-transcript (субтитры). HTML парсит сам Ragflow
- Тесты: Vitest (unit), Playwright (e2e)
- **Деплой: Coolify на .110**, фронт статикой через nginx, API как Node-сервис

## Взаимодействие с Ragflow (заменяет собственный chunker/embedder)

Каждый ноутбук = **Ragflow dataset** (id хранится в нашей SQLite). Источник (URL/файл/YouTube) заливается в dataset через:
- `POST /api/v1/datasets/{id}/documents` (для URL) — Ragflow сам качает, чанкует и эмбеддит
- `POST /api/v1/datasets/{id}/documents/upload` (для файлов)
- `GET /api/v1/datasets/{id}/documents/{doc_id}` — polling статуса парсинга
- `POST /api/v1/retrieval` — поиск top-k чанков с их текстом и метаданными (заменяет наш собственный retrieval)
- `POST /api/v1/chats` или прямой stream к LLM — для ответа (можно и самим с retrieved контекстом, см. ниже)

Стратегия чата: **сами формируем промпт** с retrieved-чанками из Ragflow, отправляем в выбранный провайдер (Anthropic/OpenAI/Ollama). Это даёт контроль над citations и форматом `[N]`-маркеров, и не зависит от встроенного chat-шаблона Ragflow.

## Провайдер-абстракция (ключевое решение)

```typescript
// packages/shared/src/providers/types.ts
export interface ChatMessage { role: 'user' | 'assistant' | 'system'; content: string }
export interface ChatRequest {
  messages: ChatMessage[]
  context: ScoredChunk[]   // retrieved chunks с citations
  temperature?: number
  stream: true
}
export interface CitationChunk {
  id: string
  sourceId: string
  sourceTitle: string
  text: string
  score: number
}
export interface LLMProvider {
  id: 'anthropic' | 'openai' | 'ollama'
  chat(req: ChatRequest): AsyncIterable<ChatDelta>
  embed(texts: string[]): Promise<number[][]>
  listModels(): Promise<string[]>
}
```

Каждый провайдер реализует интерфейс. В чате передаём `context: ScoredChunk[]`, ассистент ОБЯЗАН ссылаться на `[N]` маркеры в ответе. Бэкенд парсит маркеры, проставляет ссылки на источники.

### Этап 1: Storage & источники (1.5–2 часа)
**Schema (SQLite через Drizzle):**
```typescript
// apps/api/src/db/schema.ts
notebooks: id, title, created_at
sources:   id, notebook_id, kind ('url'|'file'|'youtube'),
           title, url, raw_text, created_at
chunks:    id, source_id, ord, text, token_count
embeddings:id, chunk_id, vec BLOB  -- сериализованный Float32Array
artifacts: id, notebook_id, title, content_md, created_at
```

**Задачи:**
1. Drizzle schema + миграция (`pnpm db:push`)
2. `POST /api/notebooks` — создать книгу
3. `POST /api/sources/url` — принять URL → парсер cheerio → сохранить raw_text
4. Парсер HTML: убрать мусор (nav, footer, ads), вытащить `<article>`/`<main>`/`<p>`
5. Чанкер: рекурсивный сплит по ~500 токенов с оверлапом 50
6. Эмбеддинги: выбор провайдера (по умолчанию OpenAI text-embedding-3-small)
7. `GET /api/notebooks/:id/sources` — список источников
8. Vitest-тесты на чанкер и парсер (моки HTML)

**Commit per task.**

### Этап 2: Retrieval & чат (2–3 часа)
**Задачи:**
1. SQLite-векторный поиск: загрузить все embeddings → косинус → top-k
2. Системный промпт: «Ты ассистент по этим источникам. Цитируй как [1], [2]. Если ответа нет в источниках — скажи прямо»
3. `POST /api/chat` (SSE): принимает `{notebookId, message}`, стримит `delta` + `citations`
4. Провайдеры: Anthropic (`messages.stream`), OpenAI (`chat.completions.create stream`), Ollama (`/api/chat` SSE)
5. UI: левая колонка — источники, центр — чат, правая — заметки
6. Markdown-рендер ответов с подсветкой `[N]` → кликабельные ссылки на источник
7. Streaming-индикатор + цитаты внизу сообщения

**Acceptance:** добавить URL → спросить «о чём?» → ассистент отвечает с `[1]`, `[2]` → клик подсвечивает чанк

---

### Этап 3: Файлы и YouTube (2 часа)
**Задачи:**
1. Загрузка файлов: drag&drop + file picker в UI
2. Парсер PDF (pdf-parse), DOCX (mammoth), TXT/MD (натив)
3. YouTube: youtube-transcript → raw_text; fallback на yt-dlp если нет субтитров
4. Прогресс-бар парсинга (server-sent events)
5. Ограничения: PDF до 50MB, DOCX до 10MB

**Acceptance:** загрузить PDF → задать вопрос → ответ с цитатами со страниц PDF

### Этап 4: Артефакты (1.5–2 часа)
**Концепция:** Артефакт = структурированная заметка. В MVP только тип «note» (markdown). Типы «chart», «mindmap», «briefing» — следующая итерация.

**Задачи:**
1. `POST /api/artifacts` — создать (title, content_md)
2. `GET /api/artifacts?notebookId=...`
3. Кнопка «Сохранить как заметку» под каждым ответом ассистента
4. Шаблон артефакта: `# Вопрос\n\n## Ответ\n\n## Цитаты\n[N] ...`
5. UI панели справа: список заметок, предпросмотр, экспорт `.md` (download)
6. Редактор: textarea с live-превью через react-markdown
7. Поиск по артефактам (простой LIKE)

**Acceptance:** сохранить 3 ответа как заметки → отредактировать → скачать → импортировать обратно

## Тесты / валидация

- **Unit (Vitest):** chunker, html-parser (на 3 фикстурах), citations parser, cosine similarity
- **Integration:** `apps/api` через Vitest с in-memory SQLite — happy path «создать ноутбук → добавить URL → спросить → получить ответ с citations»
- **E2E (Playwright):**
  1. Открыть localhost:5173 → создать ноутбук → добавить URL вики-статьи → дождаться парсинга → спросить «о чём?» → проверить наличие маркера `[1]` в ответе
  2. Сохранить ответ как артефакт → отредактировать → скачать .md
- **Линт:** ESLint + Prettier, pre-commit через simple-git-hooks
- **Verify:**
  ```bash
  pnpm install
  pnpm db:push && pnpm seed:demo   # 2 ноутбука с примерами
  pnpm dev                          # API 4001, Web 5173
  curl -N -X POST http://localhost:4001/api/chat \
    -H 'content-type: application/json' \
    -d '{"notebookId":"demo-1","message":"summarize"}' | head -20
  ```

## Риски и компромиссы

| Риск | Митигация |
|---|---|
| In-memory embeddings тормозят на 100+ чанков | Для MVP ок до ~500 чанков; в v2 — sqlite-vss или pgvector |
| Ollama на .110 может быть недоступна | UI провайдера показывает статус; fallback на OpenAI |
| Цитаты «галлюцинируют» (ассистент ссылается на несуществующий [3]) | Пост-парсинг: проверяем что каждый `[N]` есть в retrieved; иначе переспрашиваем |
| YouTube без субтитров | Чёткое сообщение об ошибке; предложение вставить URL стенограммы вручную |
| Длинные PDF (книга) | Ограничение 50MB на старте; в v2 — chunked upload + фоновый парсинг |
| Стрим SSE через nginx прокси | `proxy_buffering off; proxy_read_timeout 300s` |

## Открытые вопросы

1. **Хранилище:** SQLite ок, или сразу Postgres? Для MVP SQLite проще, апгрейд позже
2. **Авторизация:** нужна в MVP, или пока один пользователь? (предлагаю без — быстрее)
3. **Деплой:** на `.110` через Coolify (там уже поднят), или локально на маке?
4. **iOS-клиент:** в плане не предусмотрен, но архитектура API позволит позже
5. **YouTube:** только транскрибация, или ещё и кадры/скриншоты таймлайна? (в v2)
